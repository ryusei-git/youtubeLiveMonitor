# Claude → Codex の省トークン引き継ぎ

Issue ごとに新しい Codex セッションを使う。Claude から渡すのは Issue 番号と、Issue に書かれていない差分だけ。過去の会話全文、AGENTS.md、ソース全文を依頼文に貼り直さない。必要な情報の正本は GitHub Issue と現在の作業ツリーに置く。

## Claude からの依頼

Codex のターミナルへ `/new` を送って会話を新しくしてから、次の依頼文を送る。

```text
Issue #<番号> に着手してください。codex ラベルと Project の In progress は設定済みです。
補足: <Issue にない制約だけ。なければ省略>
```

ブランチ名・PR の作り方・報告の仕方は AGENTS.md に書いてあるので繰り返さない。
Issue に書き足りないことに気づいたら、依頼文ではなく **Issue 本文を直す**（正本を 1 か所に保つ）。

## レビュー後

**指摘は Claude が直す。** Codex に差し戻さない。差し戻すと、同じ Issue を読み直す
トークンと往復の待ち時間がかかり、軽量モデルでは同じ誤りを繰り返しやすいため。
Claude は PR のブランチを `git worktree add` で別ディレクトリに取り出して修正・確認し、
squash マージする（共有の作業ディレクトリでブランチを切り替えない）。

同じ種類の指摘が繰り返し出るなら、それは Issue の書き方の問題として `docs/ticket-template.md` を直す。

## Codex が読む順序

1. `git status --short --branch` と指定 Issue の本文・状態を確認する。既に与えられた AGENTS.md の全文や過去セッションを再読しない。
2. Issue に書かれたファイルから読み始める。対象の実装・「真似する既存実装」・Issue に挙がった `docs/pitfalls.md` の項目だけ読む。広域検索の出力はファイル名または短い抜粋に制限する。
3. Issue の手順どおりに最小の差分を作る。Issue に無い判断が必要になったら、推測で進めず PR 本文に「判断した点」として書く。
4. 最初は変更箇所のテストを実行し、最後に AGENTS.md 所定の全体確認を行う。長いビルドログは一時ファイルに保存し、成功時は末尾と警告の有無だけ確認する。失敗時は該当箇所だけ読む。
5. 1 コミットでプッシュして PR を作る。Project を In review にし、Claude のターミナルへ PR 番号を伝える。

## セッションをまたぐ場合

中断時だけ、Issue/PR 番号、ブランチ、変更済みファイル、通った確認、次の 1 手を Issue にコメントする。次のセッションはこのコメントと現在の作業ツリーから始め、会話ログ全体を読み直さない。作業ツリーと記録が食い違う場合は作業ツリーを優先する。

この運用は入力とツール出力の重複を減らすためのもの。必要な仕様や失敗原因の確認、AGENTS.md の必須確認は省略しない。
