# 利用者管理（Issue #2）

管理者メニューの「利用者管理」（`/users.html`）から、利用者名・権限・有効状態・登録日時・最終ログインを確認する。未ログインは「未ログイン」と表示する。パスワードハッシュはDTOに含めない。

- 一般利用者だけを無効化・削除できる。管理者・自分自身はAPIでも拒否する。
- 無効化は利用者と購読を保持し、新しいログインを拒否する。この画面には再有効化の機能はない。
- 削除では利用者と購読を削除する。共有チャンネル・録画ファイル・監査履歴は削除しない。
- 無効化・削除後の既存セッションは、次のリクエストでDBの有効状態を照合してログアウトする。既に処理中のリクエストやダウンロードを中断する機能ではない。
- セッションには利用者IDを保持する。削除後に同名で再登録しても、以前のセッションを新しい利用者として扱わない。
- 権限変更・管理者作成・任意の属性更新APIは提供しない。新規登録には従来の招待を使う。
- 監視対象の決定や録画処理は変更しない。

## API（ADMIN限定、変更操作はCSRFトークン必須）

| 操作 | パス | 成功時 |
| --- | --- | --- |
| 一覧 | `GET /api/admin/users` | 200、表示用DTOの配列 |
| 無効化 | `POST /api/admin/users/{id}/disable` | 204 |
| 削除 | `DELETE /api/admin/users/{id}` | 204 |

不存在は404、管理者・自分自身の操作は409。無効化済み利用者の再無効化は204。

## 検証

既存Javaテスト607件、JavaDoc、JavaScriptの型チェックを実行。テストファイルの新規作成・変更は行っていない。
既存のMockitoによるJVMクラス共有警告を避けるため、最終検証時だけ `JAVA_TOOL_OPTIONS=-Xshare:off` を付けて `./gradlew clean build javadoc` を実行した。本番JVMの設定は変更しない。

一時ディレクトリの別プロセス・インメモリH2で、一般利用者の403、管理者保護409、不存在404、CSRFなし403、DTOの項目、無効化後のログイン拒否、既存セッションの401、削除後の同名再登録による旧セッション再利用防止を確認した。
同環境の実ブラウザで一覧・確認ダイアログ・無効化・削除を確認。390px幅では表内だけ横スクロールし、ページ全体ははみ出さない。本番利用者を検証のために作成・変更・削除していない。

最終ビルドは警告0、型エラー0。再起動後の `bin/api.sh POST /api/monitor/check` は `checkedChannels: 20`、`java -jar build/libs/youtubeLiveMonitor-0.1.0.jar channel list` は終了コード0を確認した。
