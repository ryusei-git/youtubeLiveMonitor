# ユーザー側チャンネル画面 — タスク分割と進捗

設計の根拠は `docs/user-portal-design.md` の 5.2 節。本書は**実行単位と進捗**、および
**設計書から変更した点**を管理する。

## 設計書からの変更点（重要）

### 巡回と購読を切り離す

設計書 5.2 には「購読者ゼロのチャンネルは巡回対象から外す」と書いてあるが、**これは採用しない。**

既存の 19 チャンネルは誰にも紐づいていない（購読の概念が無い時代に登録されたため）。
購読を巡回の条件にすると、**この 19 件の監視が即座に全停止する**。

**今回は巡回ロジックを一切変更しない。** 購読はあくまで「画面に出す範囲」を決めるだけで、
巡回・録画・通知は従来どおりチャンネル単位で動く。
YouTube の配信中判定はクォータを消費しないため、購読者ゼロのチャンネルを巡回し続けても実害はない。

### 録画設定はユーザー画面に出さない

`recordEnabled` / `recordTitleKeywords` は**チャンネル単位**の設定なので、
ユーザー A が変えるとユーザー B にも影響する。購読ごとに持たせるのは通知の
ユーザー別化（設計書 5.3）と一緒にやる方が整合的なため、今回は触らない。
録画の制御は管理者画面のみ。

## 分割の原則

**各タスクは、終わった時点で `./gradlew clean build javadoc` が警告ゼロで通り、
アプリが従来どおり動くこと。** 「新規追加だけのタスク」を先に、「既存を変更するタスク」を後に置く。

## 進捗

| # | タスク | 既存への影響 | 状態 |
|---|---|---|---|
| 3-1 | `UserSubscription` エンティティ・リポジトリ | なし（追加のみ） | 完了 |
| 3-2 | 購読のサービスと API（一覧・追加・解除） | なし（追加のみ） | 完了（お試し版） |
| 3-3 | ユーザー画面 `my-channels.html` と認可 | ナビを変更 | 完了（お試し版） |

**完了したタスクは、担当したエージェントがこの表の「状態」を「完了」に更新すること。**

## 絶対に守ること

- **ユーザーの「解除」で消えるのは自分の購読だけ。**
  チャンネル本体・他人の購読・録画履歴・通知履歴には一切触れないこと。
  現在の管理者画面 `channels.html` はチャンネル本体を削除できるので、**明確に別物として作る**
- **同じチャンネルを複数人が購読できる。** 巡回は 1 回で済ませたいので、
  `channels` は増やさず `user_subscriptions` だけを増やす
- **チャンネルの登録は必ず `MonitoredChannelService.register()` を通す**
  （プラットフォームごとの識別子解決を迂回しない。CLAUDE.md 参照）
- **巡回・録画・通知のコードは変更しない**

## 各タスクの完了条件（共通）

1. `./gradlew clean build javadoc` が**警告ゼロ**
2. `npx -y -p typescript tsc -p src/main/resources/static/jsconfig.json --noEmit` が**型エラーゼロ**
3. 画面ファイルや jar を変更したら **`./gradlew build -x test` の後に `bin/service.sh restart`**
4. **既存機能が壊れていないこと**を実機で確認
   - `POST /api/monitor/check` で巡回が従来どおり動く（現在 19 チャンネル）
   - `java -jar build/libs/*.jar channel list` で CLI が動く
   - 管理者でログインして `channels.html` が従来どおり使える
5. この表の「状態」を更新する

## 触ってはいけないもの

- `data/`（実データ。手動 ALTER が必要なら**実行せず報告**）
- `.env`（管理者パスワードが入っている）
- `recordings/` の既存ファイル
- `LiveStreamPollingScheduler` / `StreamRecorder` / 通知まわり

## お試し版として作った範囲（2026-09-22）

`UserSubscriptionService` / `MyChannelController`（`/api/my/channels`）と
`my-channels.html` を追加し、ログイン中の利用者が自分の購読を追加・解除できるようにした。

**併せて権限を閉じた。** `/channels.html` などの管理者向け画面は
`anyRequest().authenticated()` に落ちており、**一般利用者でもチャンネル本体を削除でき、
通知履歴・録画履歴まで連鎖削除できる状態だった**。ユーザー画面を追加するにあたり、
管理画面・管理APIと録画ファイル（`/recordings/**`）を ADMIN 限定にした。
一般利用者のログイン後の遷移先も `/channels.html` から `/my-channels.html` に変えた
（入れない画面へ飛ばしていたため）。

この変更に伴い `SecurityConfigTest` の2件を新しい挙動に合わせ、
「USER が管理画面に入れないこと」の検証を1件追加した（利用者の承諾済み）。

### まだ無いもの

- **USER 権限のアカウントを作る手段が無い。** `AdminUserInitializer` は ADMIN しか作らず、
  利用者の登録・管理画面も未実装。そのため**実際の USER での動作確認ができていない**
  （管理者アカウントで API と画面の動作は確認済み）。
- 通知のユーザー別化（設計書 5.3）・ダウンロード（5.5）・横断検索（5.4）は未着手。
  ユーザー画面のナビは「マイチャンネル」1項目だけ。
